🎯 Overview Sistem

Sistem PO Management adalah aplikasi web berbasis Laravel untuk mengelola Purchase Order (PO) secara menyeluruh, mulai dari pembuatan, approval, pembayaran, hingga penerimaan barang.

Tujuan Sistem

  • Mempermudah pengelolaan pembelian barang/jasa
  • Menyediakan workflow approval yang terstruktur
  • Memantau status pembayaran dengan sistem termin
  • Menghasilkan dokumen PO dalam format PDF profesional
  • Mengelola data master (produk, kategori, vendor, cabang)

Keunggulan

Sistem persetujuan bertingkat dengan tanda tangan digital untuk setiap PO.

Fitur Penerimaan Barang

  • Penerimaan Per-Item: Pilih item mana yang diterima via modal checkbox
  • Partial Quantity: Bisa terima sebagian dari quantity order (misal: order 100 pcs, terima dulu 50 pcs)
  • Fleksibel: Tidak tergantung status pembayaran
  • Tracking Status: Status otomatis ter-update (Not Received → Partial → Received)

📚 Master Data

1. Kategori Produk

Pengelompokan produk berdasarkan jenis atau fungsinya.

Field Tipe Keterangan
name String Nama kategori (wajib, unik)
slug String URL-friendly name (auto-generate)
description Text Deskripsi kategori (opsional)

2. Produk

Data barang/jasa yang dapat dipesan dalam PO.

Field Tipe Keterangan
sku String Stock Keeping Unit (unik)
name String Nama produk
category_id Foreign Key Referensi ke kategori
unit String Satuan (pcs, kg, box, dll)
price Decimal Harga default per unit
description Text Deskripsi produk

3. Vendor

Data supplier/pemasok barang.

Field Tipe Keterangan
name String Nama perusahaan vendor
code String Kode vendor (unik)
email String Email kontak
phone String Nomor telepon
address Text Alamat lengkap
contact_person String Nama kontak person

4. Cabang

Data cabang/lokasi perusahaan yang memesan barang.

Field Tipe Keterangan
name String Nama cabang
code String Kode cabang (untuk nomor PO)
address Text Alamat lengkap
phone String Nomor telepon
npwp String Nomor NPWP
logo_base64 Text Logo dalam format Base64

5. Payment Terms (Skema Pembayaran)

Template skema pembayaran yang dapat dipilih saat membuat PO.

Field Tipe Keterangan
name String Nama skema (Net 30, DP 50%, dll)
days Integer Jumlah hari jatuh tempo
payment_type Enum full (penuh) atau partial (cicilan)
installments JSON Konfigurasi cicilan (persentase & hari)
Contoh Installments JSON:
[{"percentage":30,"days":0,"description":"DP 30%"},{"percentage":70,"days":30,"description":"Pelunasan 70%"}]

📋 Purchase Order Management

Format Nomor PO

Nomor PO di-generate otomatis dengan format:

XXX/GA/BRANCH_CODE/ROMAN_MONTH/YY

Contoh: 001/GA/PLJKT/I/25
- 001        : Nomor urut (reset setiap tahun)
- GA         : Kode tetap (General Affairs)
- PLJKT      : Kode cabang
- I          : Bulan dalam angka Romawi
- 25         : Tahun (2 digit)

Komponen Purchase Order

Komponen Deskripsi
Header Nomor PO, tanggal, vendor, cabang, payment term
Details List item (produk, qty, harga, diskon, subtotal)
Footer Subtotal, PPN (11%), Total, Notes
Signatures Tanda tangan pembuat dan approver

Fitur Detail PO

  • Multiple Items: Dapat menambahkan banyak produk dalam satu PO
  • Diskon per Item: Diskon dalam persentase per item
  • PPN: Kalkulasi PPN 11% otomatis
  • Custom Price: Harga dapat diubah dari harga default produk
  • Notes: Catatan khusus untuk vendor

Membuat PO Baru

  1. Klik menu Purchase Orders → Create New
  2. Pilih Vendor dan Cabang
  3. Pilih Payment Term (skema pembayaran)
  4. Tambahkan produk dengan klik + Add Product
  5. Isi jumlah, harga, dan diskon (jika ada)
  6. Tambahkan notes jika diperlukan
  7. Klik Save as Draft

Submit untuk Approval

  1. Buka detail PO yang berstatus Draft
  2. Klik tombol Submit untuk Approval
  3. Gambar atau upload tanda tangan
  4. Konfirmasi submit
  5. Sistem akan mengirim email notifikasi ke Manager

Approval Process (Manager)

  1. Manager menerima notifikasi email
  2. Buka detail PO yang berstatus Pending
  3. Review item dan total PO
  4. Pilih Approve atau Reject
  5. Jika approve: gambar/upload tanda tangan
  6. Jika reject: masukkan alasan penolakan

Print PDF

PO yang sudah Approved dapat dicetak dalam format PDF yang berisi:

  • Logo dan informasi cabang
  • Informasi vendor
  • Tabel detail item
  • Total dan PPN
  • Tanda tangan pembuat dan approver

💰 Manajemen Pembayaran

Sistem Termin

Setelah PO di-approve, sistem otomatis membuat jadwal pembayaran berdasarkan Payment Term yang dipilih.

Contoh Skema Pembayaran:

Skema Termin 1 Termin 2 Termin 3
Net 30 100% (30 hari) - -
DP 50% 50% (segera) 50% (30 hari) -
Termin 3x 30% (segera) 30% (30 hari) 40% (60 hari)

Mencatat Pembayaran

  1. Buka detail PO yang sudah Approved
  2. Pada bagian Jadwal Pembayaran, klik tombol Bayar
  3. Masukkan jumlah yang dibayar
  4. Tambahkan catatan (nomor bukti transfer, dll)
  5. Klik Simpan Pembayaran

Status Pembayaran

Status Kondisi Warna Badge
Unpaid Belum ada pembayaran sama sekali Abu-abu
Partial Sudah ada pembayaran tapi belum lunas Kuning
Paid Semua termin sudah dibayar lunas Hijau
⚠️ Penting: Penerimaan barang baru dapat dilakukan setelah status pembayaran Paid.

👥 User & Role Management

Sistem Role

Sistem menggunakan Spatie Laravel Permission untuk manajemen role dan permission.

Role Deskripsi Kemampuan Utama
Admin Administrator sistem
  • Kelola semua user
  • Kelola role & permission
  • Approve PO
  • Akses semua fitur
Manager Approver PO
  • Approve/Reject PO
  • Lihat semua PO
  • Kelola master data
Staff Pembuat PO
  • Buat PO baru
  • Edit PO draft milik sendiri
  • Submit PO untuk approval
  • Catat pembayaran

Daftar Permission

Permission yang tersedia dalam sistem:

  • manage-products - Kelola produk
  • manage-vendors - Kelola vendor
  • manage-branches - Kelola cabang
  • manage-payment-terms - Kelola payment terms
  • manage-purchase-orders - Kelola PO
  • approve-purchase-orders - Approve PO
  • manage-users - Kelola user
  • manage-roles - Kelola role
  • manage-permissions - Kelola permission
